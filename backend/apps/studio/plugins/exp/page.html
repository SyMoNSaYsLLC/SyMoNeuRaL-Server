Mounted

The entry table, exactly as the runtime holds it — what is mounted, what it asked to be injected with, what is missing, and which fiber is carrying it. Reads need no token, so this table is visible to anyone; one thing is withheld from a tokenless reader and it is named precisely, an entry's config, because that is where a plugin's credentials would live.

Services

The container, keyed by realm rather than by name. Two isolated sessions that each provide llm are two rows here and not one — collapsing them would hide the exact thing isolate() exists to make visible. epoch counts how many times a name has been re-provided without leaving the container in between, so anything holding a stale value can compare and re-resolve. A plugin that unloads takes its service out with it, and the replacement starts at one again — an epoch of one next to a fresh object means a reload, not a missed count.

Trace

Append-only, polled from the last sequence number this page saw — a sequence and not a timestamp, because two events can share a millisecond and a timestamp cursor either re-delivers one or drops it. Neither is acceptable in the feed you debug a reload from.

Call a method on a live service

Any method on any mounted service, with whatever arguments are posted. There is no allow-list: a plugin runtime whose services can only be poked through endpoints written in advance is a runtime you cannot experiment with, and experimenting is what this app is called. The token is the line.

Mount one plugin

The catalogue below is described by importing each module and reading its signature, not by a hand-kept list, so this control cannot offer a plugin the runtime cannot resolve. Adding one entry touches nothing else that is mounted. Patch ignores the plugin box and replaces the config of the entry whose id is in the id box, restarting just that fiber — the config button on a row fills both fields for you.

The example plugins

Seven of them, each demonstrating one idea rather than doing anything useful. Kind is not a label typed into this page -- it is what the registry decided by looking at the object it resolved, which is why six of these read module and one reads class: a manifest's use: line names a module. The runtime accepts two more shapes, a plain function and an object with an apply attribute, and no example here uses them.

PluginKindWantsWhat it demonstrates

Nothing on this page is a sandbox and the runtime does not claim to be one. A plugin runs in this process with this process's privileges; isolate() decides which object a plugin sees under a service name, which is a composition boundary and not a security one. In-process isolation of Python from Python is not achievable — the seam for real isolation is out-of-process, and it is documented rather than pretended.
