### 1. CUDA occupancy fix — the one real disagreement with the CUDA guide *(~1 h)*
`symoneural_reinforce/symoneural/compute/ops.py`

**Two call sites duplicate the same hardcoded expression. Fix both or fix neither:**
- `ops.py:259` (inside the cooperative reduction)
- `ops.py:283` (`cooperative_grid_size()`)

```python
# All blocks must co-reside: cap at 2 blocks/SM for a 256-thread block
# against the 1536 threads/SM this part supports.
grid = max(1, min(self.sm_count * 2, (n + block - 1) // block))
```

The guide (≈line 36990 of `run/cuda/guide.txt`) requires computing it:

```c
cudaOccupancyMaxActiveBlocksPerMultiprocessor(&numBlocksPerSm, my_kernel, numThreads, 0);
dim3 dimGrid(deviceProp.multiProcessorCount*numBlocksPerSm, 1, 1);
```

**Why it matters:** occupancy depends on the kernel's *register and shared-memory* use, not just
thread count. If someone edits the kernel and occupancy drops to 1 block/SM, `grid.sync()` either
fails to launch or hangs. The hardcoded 2 is right today and fragile tomorrow.

**Known blocker (this is where the previous session stopped):**
`KernelCache.__init__` is `(self, arch: str, std: str = "c++17")` at
`symoneural_reinforce/symoneural/compute/program.py:103` — it takes an **arch string, not a
context**. `ctx.caps` exposes `arch`, `compute_capability`, `sm_arch`. That construction shape
needs sorting before the occupancy query can be wired and tested.
`cuOccupancyMaxActiveBlocksPerMultiprocessor` **is** available in the installed bindings —
confirmed.

**⚠ Coupled text you must update in the same change — three places assert the hardcoded answer:**
1. the docstring at `ops.py:245-252` ("cap at 2 blocks/SM")
2. the docstring at `ops.py:283` ("140 on this part")
3. **`site/index.html:494`** — *"The single-pass reduction caps its grid at 140 co-resident
   blocks…"*

If you compute occupancy dynamically and leave those saying 140, you have published a number the
code no longer produces. That breaks the project's own labelling rule. Either update all three to
describe the computed value (and state 140 as the *measured result on this part*), or don't ship
the change.

## 7. Rules that must not be re-broken

Every one of these is here because breaking it cost real time. `CLAUDE.md` is the fuller version.

**GPU**
- One RTX 5070 Ti, 15.92 GiB. Chat (~5 GB), image (~7 GB) and a QLoRA run (~12 GB) **cannot
  coexist**.
- Everything touching the GPU goes through `gpu-governor.sh`, ideally
  `gpu-governor.sh with <surface> -- <cmd>`, which releases even on crash.
- **Lock per job, never for a process lifetime.** Residency (weights loaded) and work (using the
  card) are separate things. Holding the lock while a model is merely resident locks out every
  other process — including the CLI — until the 300 s acquire timeout.
- **Never call a bare `release`.** Always name the surface: `release chat`. An unscoped release
  once destroyed a running fine-tune's lock from the API's shutdown hook.
- The governor waits for VRAM to drain below a **1.5 GB floor** between tenants. Killing a process
  returns the lock before CUDA has torn down, and the next tenant OOMs at step 0.
- **RavenCalc (SymPy, CPU) deliberately never takes the lock.** That is precisely what lets it
  speculatively pre-compute while the GPU is loading. Do not "fix" this.
- Image generation needs these argv flags or it OOMs at 768² (the VAE wants a 3.74 GB compute
  buffer while T5 holds 5.2 GB): `--backend te=cpu --vae-tiling --diffusion-fa`.
- **Restarting the API** (you will do this after every `api.py` edit in queue item 0). Prefer
  `symoneural.sh off` then `on`, or `systemctl restart symoneural-api` once the unit is
  installed. If you must do it by hand, **let the API stop `llama-server` itself** and then wait
  for VRAM to drain before starting anything else:
  ```bash
  kill "$(pgrep -f '[a]pi\.py')"; sleep 3
  pkill -f '[l]lama-server'; sleep 2          # bracket pattern -- plain -f kills your own shell
  nvidia-smi --query-gpu=memory.used --format=csv,noheader   # wait for < 1500 MiB
  cat run/gpu.lock.d/holder 2>/dev/null || echo free    # confirm the lock is not stranded
  ```
  I used exactly this sequence at 19:29 and it was clean (drained to 973 MiB, lock free), but be
  aware it is the pattern CLAUDE.md warns about: **killing a process returns the lock before CUDA
  has torn down.** Always check VRAM and the holder before the next tenant starts, or it OOMs at
  step 0.

**Python**
- The base interpreter is pinned at **exactly 7 packages** and must never be extended — check with
  `pip freeze | wc -l`. `numba-cuda` silently downgrades numpy; three other packages pin
  conflicting `cuda-core`/`cuda-python` versions.
- The serving API uses **only the system interpreter** — fastapi, uvicorn and sympy are already OS
  packages, so there is **no virtualenv in the serving path**. This is a design decision, not an
  oversight.
- Training has its own venv at `training/.venv`. Anything else that conflicts gets its own
  isolated venv.

**Honesty — this is the product, not decoration**
- Label every figure **measured** on this machine / **vendor** specification / **projected**
  arithmetic. **Never present a projection as a result.**
- **Never invent pricing.** Direct pricing questions to symonsayadmin@symoneural.com.
- **No decorative status indicators.** Every LED and gauge reflects a real reading.
- **Publish negative results** — the PCIe Gen 3 ×8 ceiling and the failed multi-stream overlap are
  on the site deliberately. They are the credibility.
- **Layout changes must not drop data.** Fold long content into `<details>`; never trim.

**Builds**
- Generator scripts are **idempotent and must stay that way** — `build_console.py` once nested
  folds inside folds when run twice.
- `build_pages.py`, `build_rack.py`, `build_console.py`, `build_stack.py`, `build_cost.py`,
  `build_training.py` **all rewrite files under `site/`**. Never run two in parallel; two writers
  in that directory clobber each other.
- Safe parallel tracks for subagents: read-only audits, brand-new standalone files, docs, tests.
- **Run as many agents concurrently as quality allows** — this is an explicit standing instruction
  from the user. Compiles and fine-tunes occupy the machine for tens of minutes; fill that
  wall-clock with independent work. Launch them in a single message so they actually run in
  parallel.

**Branding**
- "MIT AI Training" is purged everywhere user-facing. **Never blind-replace `MIT`** — most matches
  in this corpus are ordinary words: limits, limited, submit, emits. Whole phrases and local
  filesystem paths only.

**Shell traps that have bitten before**
- `pkill -f llama-server` **kills your own shell** (the pattern matches the command line running
  it). Use a bracket pattern: `pkill -f '[l]lama-server'`.
