RavenCalc does not use the GPU. This is the card the rest of the stack shares, shown here so you can see what it is doing; nothing on this page waits for it.

Applied to

The keys type the engine's own notation, which is the language it actually reads: ** for a power, sqrt(x), Abs(x), pi and E as exact constants, oo for infinity. You can type it yourself as well — the box is a plain text field.

Symbolic in, symbolic out — you get an exact answer rather than a float that already lost the argument. An antiderivative is differentiated back and simplified against zero before you see it, and if that check cannot confirm the result it says so rather than rounding up to “verified”.

System information — one card, one surface at a time

This is a 16 GB consumer card, and it is a test bench

Chat and image never run at the same time here. A lock hands the GPU to exactly one surface and the other waits, because both weight sets do not fit in 15.92 GiB at once — and when they swap, we wait for the driver to actually hand the memory back before the next one starts. If you are queued behind someone, that is not a bug; it is one card doing one thing at a time.

RavenCalc is the exception — it is symbolic algebra on the CPU, so it never touches the GPU and never queues. Everything here is a demonstration of the stack on the smallest machine we would ever ship, not a statement of capacity. A server we spec for you would not be sharing one GPU with itself.
