Starting this takes the card from everything else. The miner holds the GPU lock for its whole process lifetime, not for a job, and it is not preemptible: an arriving chat or image request spins in the governor’s acquire loop for up to its 300 s timeout and then gives up. Measured on this box, with the timeout cut to ten seconds to show it rather than wait it out: gpu-governor.sh acquire chat 10 against a live miner logs 'chat' TIMED OUT after 10s behind 'miner'. That is why nothing here starts by itself, and why it should be stopped deliberately rather than left holding the card on a box that also serves chat and image.

What the emulator is and is notQEMU, no hashboards

QEMU runs the control board’s ARM cores. It does not emulate the FPGA fabric or the links to the hashboards — those are the part that is not there. So the firmware’s web UI and its upgrade path run, and bmminer does not: with the miner’s own init the firmware finds no hashboards and reboot-loops, which is correct behaviour and useless as a target.

It is a good way to work on flashing without risking a rig. It is not a substitute for hardware when testing telemetry.

SyMoNeuRaL Miner is the one surface here that holds the card for its whole process lifetime rather than for a single job, and it cannot be preempted. While holding reads miner, chat, image and remix will queue and then fail — which is why it is started by hand and stopped by hand.

A benchmark from August, not current telemetry

52.3 – 53.2 MH/s on KawPow — measured on this machine across four runs, RTX 5070 Ti at a 300 W limit, driver 610.57.04, kawpowminer 1.2.4, 2026-08-17. The miner’s own summary for the longest run reads Max 53.209880 Mh Mean 53.026032 Mh. A short run reads lower because its mean includes spin-up, not because the card slowed down. The spread across runs is quoted rather than the best figure and no cause has been established for it.

This tree cannot reproduce it. The figures came from somebody else’s binary, and the script that built it — contrib/build-kawpowminer.sh — is not tracked in this repository, so a clone has no path from source to a running miner. Read the numbers as provenance: evidence of what this card did once, on a dated run, with a named binary. They are not a claim about what the surface does now, and nothing on this page reports them as live telemetry.

All four were benchmarks against no pool. A miner with nowhere to submit a share earns nothing whatever its hashrate says, so the surface reports hashrate and income as two separate claims — and publishes no income figure at all, because that depends on network difficulty, pool fees and the RVN price, none of which this box measures. One miner, two kinds of hardware

The rack lists one SyMoNeuRaL Miner. Under it are two halves that fail independently, so this page gives each its own card and its own status chip rather than averaging them into a single light.

GPU · Ravencoin is the card in this box — the intended KawPow path for the RTX 5070 Ti, and the only half of this surface that has ever hashed, on the dated 2026-08-17 benchmark above. It is also the only half that takes the GPU, which is why the merged row reports busy whenever it is running: that is a fact every other surface on this machine feels. The engine work is incomplete, so it is offline here rather than hashing.

ASIC · Antminer + MicroBT reads rigs on your own network, and carries a firmware emulator and a network scanner — the two parts that do real work with no rig attached. It reports offline here because none is attached and the surface is switched off, and that is the reading rather than a placeholder.

They keep separate tokens and separate routes. They were two rack rows until 2026-08-17 — SyMoNeuRaL Miner, offline with no rig attached, beside SyMoNeuRaL Miner GPU, which was the one actually hashing. The plain product name was on the dead row and the working one wore a qualifier, so the pair read as a single half-broken surface.

What the switches actually switch

SYMONEURAL_ASIC_ENABLED does not enable a rig and does not enable mining. It enables these operator controls on this server — scan, firmware listing, emulator — and with SYMONEURAL_ASIC_TOKEN unset they stay off, so a misconfigured box serves nothing here rather than serving an unauthenticated scanner. The scanner also refuses any range that is not private, so it cannot be aimed at the internet from this host.

You do not need either variable to run the QEMU emulator. SYMONEURAL_ASIC_ENABLED=1 and SYMONEURAL_ASIC_TOKEN gate the HTTP API only; scripts/qemu-antminer.sh runs without them. Setting them will not make an emulator report a hashrate either, because QEMU emulates the Zynq CPU and not the hashboards — so nothing answers on port 4028, and that is the emulator working correctly rather than a misconfiguration. The value is compared as the literal string 1: true, yes and on all leave the surface off.

The GPU miner above has its own pair, SYMONEURAL_MINING_ENABLED and SYMONEURAL_MINER_TOKEN, and the two tokens must not be the same string: this one authorises reading rigs, that one authorises taking the card away from every other surface.

System information — one card, one surface at a time

This is a 16 GB consumer card, and it is a test bench

Chat and image never run at the same time here. A lock hands the GPU to exactly one surface and the other waits, because both weight sets do not fit in 15.92 GiB at once — and when they swap, we wait for the driver to actually hand the memory back before the next one starts. If you are queued behind someone, that is not a bug; it is one card doing one thing at a time.

RavenCalc is the exception — it is symbolic algebra on the CPU, so it never touches the GPU and never queues. Everything here is a demonstration of the stack on the smallest machine we would ever ship, not a statement of capacity. A server we spec for you would not be sharing one GPU with itself.
