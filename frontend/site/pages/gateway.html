How a licence would clear

  1. Contract (on-chain). A licensing contract on the TRON Virtual Machine, denominated in USDT (TRC-20) rather than a native token.
  2. Daemon (off-chain). Runs on the operator’s own machine. It hashes the build logs into a reviewable tree and pauses for a human to approve the configuration before anything is broadcast. No blind script touches a rig.
  3. Energy. TRON meters execution as Bandwidth and Energy rather than a gas auction. Renting Energy moves the execution cost off the end user.
  4. Settlement. The daemon broadcasts the validation state and the payment. Once DPoS confirms it, the settlement is read back off the chain and checked field by field — payer, token, amount, workspace — and a short-lived entitlement is issued for the workspace it covers.

One thing this is not: a copy-protection scheme. A blockchain is public, so a key published to it is published to everyone, and any arrangement that actually withholds one puts a server we run in the loop — which makes that server the authority and the chain a payment rail. So we call it a payment rail. Settlement is final, auditable and needs no card processor; that is the whole of the claim, and it is worth having. The encryption at rest is real and is not load-bearing against a determined licensee.

Every figure here is someone else’s

~3 second confirmation and 27 Super Representatives are vendor figures — published parameters of the TRON network, not timings taken on this machine. Block times are a target, not a guarantee.

“Effectively zero fee” is projected. Energy rental does not make execution free; it moves the cost from the end user to whoever rents the Energy. Calling that zero would describe an accounting choice as a physical property.

What is measured here comes from the chain reader — head block, whether a contract exists at the configured address, and how long the node took to answer. It runs off the request path and its age is printed with it, because “real, and 40 seconds old” is a different claim from “real right now”. When the surface is switched off there is no reading to show, and the status line says that rather than showing a stale one.

What is, and is not, on this box

There is no wallet, no private key and no signing code in the process serving this page. Reading a public chain needs none of them: the calls this box makes are unauthenticated, and it cannot build, sign or broadcast a transaction — its own test suite asserts that.

The licensing logic is split along the same line. Checking a licence needs only public information, so it runs here: reading the settlement off the chain, confirming the payer, the token, the amount and the workspace all match, and verifying an entitlement against a public key. Issuing one needs a private key, so it does not run here and cannot. A break-in on this box could read licences and could not mint one.

Signing lives on the operator’s own machine. Whether a contract is deployed, and what is at that address, is not claimed on this page — it is read from the chain and reported in the status line above, so this page cannot come to disagree with the machine.

System information — one card, one surface at a time

This is a 16 GB consumer card, and it is a test bench

Chat and image never run at the same time here. A lock hands the GPU to exactly one surface and the other waits, because both weight sets do not fit in 15.92 GiB at once — and when they swap, we wait for the driver to actually hand the memory back before the next one starts. If you are queued behind someone, that is not a bug; it is one card doing one thing at a time.

RavenCalc is the exception — it is symbolic algebra on the CPU, so it never touches the GPU and never queues. Everything here is a demonstration of the stack on the smallest machine we would ever ship, not a statement of capacity. A server we spec for you would not be sharing one GPU with itself.
